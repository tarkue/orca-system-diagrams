# Модель через штатный чат Orca

Агент исследует настоящий проект и редактирует одну модель; панель отображает результат сборки. Для своей модели используйте клонированный репозиторий расширения и development-пакет: [установка](INSTALL.md).

Пример запроса агенту:

> Изучи фактические исходники выбранного проекта. Обнови `orca-plugin/model.json` по `SystemModel` из `src/core/model.ts` и правилам `src/core/validation.ts`: архитектуру, связи, workflow, сущности, состояния и стек. Сохрани стабильные ID, увеличь version при изменении модели. Не выдумывай технологии, протоколы, таблицы и поведение; укажи неопределённость в описаниях. Поясни, какие данные подтверждены кодом, а какие являются логическим представлением. Выполни `npm run build` и сообщи фактический результат; отдельно назови запущенные тесты и ограничения проверки.

После изменений поведения, архитектуры, сущностей или стека обновляйте соответствующие поля модели и повторяйте сборку. Используйте конечную команду сборки, а не постоянный сервер. Проверьте новое имя/версию в панели; reload сам по себе не подтверждает правильность архитектуры или прохождение тестов.

Агент выполняет обычную работу с файлами в разрешённом ему контексте. Панель не инициирует агентные вызовы, не получает автоматически результат каждого сообщения и не выбирает модель произвольного focused project. Для другого проекта источник нужно подготовить явно.

В отчёте различайте реальное выполнение агента, локальные команды, тестовые fixtures и симуляцию host. Синтетические примеры не являются обнаруженной архитектурой, а логическая ER-модель не доказывает наличие базы данных. Если сборка не прошла, сообщите ошибку: прежний HTML не является новым результатом.

Готовая копируемая установка требует обновления пакета вручную через штатную установку. Development-папка `orca-plugin/package` получает автоматическую перезагрузку после успешной сборки. [Схема и ограничения данных](MODEL.md).
