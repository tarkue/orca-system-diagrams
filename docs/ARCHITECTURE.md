# Архитектура

Поставка — нативное расширение Orca с одной панелью. Оно использует `workspace:read`, без worker. Чат и выполнение задач принадлежат Orca; панель не запускает агентов, терминальные команды или отдельный backend.

```text
Штатный агент Orca исследует исходники
  → редактирует orca-plugin/model.json
  → npm run build
  → runtime-валидация и сборка HTML
  → orca-plugin/package
  → development watcher Orca
  → нативная панель: шесть представлений + инспектор + JSON
```

`src/core/model.ts` задаёт `SystemModel`, `src/core/validation.ts` проверяет данные и ссылки графа. `orca-plugin/model-input.mjs` читает JSON, ограничивает вход 512 KiB и безопасно встраивает его в HTML. `scripts/build-plugin.mjs` собирает код, стили и модель в пакет; некорректная модель останавливает сборку до замены панели.

`src/notations/render.ts` строит SVG и соответствия элементов идентификаторам модели. C4, EPC и ER используют специализированные представления; BPMN — bpmn-js, Sequence и State — Mermaid. Все виды происходят из одной модели, а не из шести независимых рисунков. [Семантика нотаций](NOTATIONS.md).

Инспектор связывает список элементов и выбранную фигуру; JSON доступен только для чтения. UI хранит состояние представления, а исходная модель живёт в файле. Сеть для загрузки кода, CSS или шрифтов панели не требуется.

Development watcher отслеживает собранный пакет, а не исходный JSON. Обычная установка копирует пакет и требует повторной установки обновления. Host metadata не является доступом к произвольному репозиторию: смена активного проекта не меняет источник модели.

Публичные исходники предназначены для plugin-only сборки. `npm run dev` — локальный preview viewer для разработки; это не способ нативной установки. Автоматического chat-completion hook, сканера репозитория и механизма сохранения файлов из панели нет. [Границы совместимости](COMPATIBILITY.md).
