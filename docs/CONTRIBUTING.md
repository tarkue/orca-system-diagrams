# Участие в разработке

Ошибки и предложения: [GitHub Issues](https://github.com/tarkue/orca-system-diagrams/issues). Для ошибки укажите версию Orca, версию расширения, шаги воспроизведения и обезличенный минимальный пример модели. Не публикуйте приватные исходники, пути, идентификаторы рабочих сессий или историю переписки.

## Локальная работа

Нужны Node.js 22.12+ и npm. После клонирования репозитория:

```sh
npm ci
npm test
npm run test:bridge
npm run build
npm run verify:plugin
```

Дополнительные команды:

| Команда | Назначение |
| --- | --- |
| `npm run dev` | локальный preview viewer, не нативная установка |
| `npm run package:plugin` | сборка ZIP и SHA256 |
| `npm run build:site` | сборка статического сайта |

Опциональная проверка с установленным macOS host: `node scripts/verify-plugin.mjs --installed-host`. Она предназначена для проверенной Orca 1.4.218; отсутствие host не должно мешать переносимой проверке.

Для нативного цикла подключите `orca-plugin/package` как development-папку и повторяйте конечную `npm run build`. Подробности — в [установке](INSTALL.md).

## Требования к изменениям

Сохраняйте единую валидируемую модель, стабильные идентификаторы и честную семантику каждой нотации. Для значимых изменений модели и bridge добавляйте содержательные тесты, включая неверные данные и ссылки. При изменении архитектуры обновляйте модель и документацию.

В PR опишите наблюдаемое изменение, реально выполненные проверки и ограничения. Разделяйте unit tests, browser preview, simulated host и реальную загрузку в Orca. Не заявляйте нативную совместимость по одному успешному build.

Не добавляйте отдельное приложение, сервер, второй чат, финансовые формы или ручной JSON exchange UI. JSON остаётся только для чтения; работа агента идёт через native chat. Сохраняйте notices зависимостей и видимый linked watermark bpmn.io. Оригинальный код проекта распространяется по MIT.

Перед публикацией изменений выполните npm run prepare:git-install и включите обновлённые orca-plugin.json и plugin/ в commit. CI проверяет синхронизацию готового Git-пакета с исходниками.
